01

DESIGN PRINCIPLES

工具服务创作者，平台服务工具。

Tools serve creators. The platform serves the tools.

Local-first

本地优先

Local by default

源数据、正式资产、Bridge 与 Runtime 默认在开发者设备中工作。网络与远程模型始终是显式选择。

Source data, production assets, bridges, and runtimes stay on the developer's machine by default. Network access and remote models are explicit choices.

Engine-neutral

设计意图独立

Intent stays portable

BAIGE IR 描述领域语义，不把创作内容锁在某个引擎的私有资产结构中。

BAIGE IR describes domain intent without binding authored content to a proprietary engine asset format.

Human-controlled

人工最终确认

Human approval

LLM 只提出经过 Schema 校验的 Patch。每项变更都可以比较、拒绝、撤销并记录批准链。

LLMs only propose schema-validated patches. Every change can be compared, rejected, reverted, and recorded.

Open & portable

开放且可迁移

Open and portable

开放 Schema、Bridge Protocol 和参考 Runtime；即使不再使用 Studio，项目数据仍可被读取与维护。

Schemas, the Bridge Protocol, and reference runtimes remain open, so project data stays maintainable without BAIGE Studio.

03

PRODUCT FAMILY

独立命名，共同署名。

Independent names. One family signature.

Official product

A BAIGE Project

未来 AI、任务、对话、战斗等领域工具不会被命名为“BAIGE + 功能名”。每个工具拥有来自统一文化命名体系的独立名称，再以 A BAIGE Project 标明官方血统。

Future AI, quest, dialogue, combat, and other tools keep independent product names. A BAIGE Project is the shared official family mark.

Shared infrastructure

BAIGE Foundation

BAIGE Studio、BAIGE IR、Bridge Protocol、Runtime 与 @baige/* 属于技术基础设施，因此使用统一 BAIGE 技术命名。

BAIGE Studio, BAIGE IR, the Bridge Protocol, runtimes, and @baige/* are shared infrastructure and use the BAIGE technical namespace.

产品命名规则已经作为仓库规范固化。

Product naming is now a repository-level rule.
