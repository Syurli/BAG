# AI 开发与编辑约束

本规范同时约束“使用 Codex 开发 BAG（百舸）”与“最终产品中的 LLM 编辑功能”。产品命名与品牌展示同时受 `PRODUCT_NAMING.md` 约束。

## A. Codex 开发约束

### A1. 任务契约

任何超过单文件的任务都应先定义范围、接口、验收测试、禁止区域和回退方案。代理不得把模糊目标扩张成跨模块重构。

### A2. 架构保护区

以下内容未经维护者批准不得改变语义：

- BAG IR 核心类型；
- 坐标与单位规范；
- 时间锚点与执行顺序；
- Bridge 握手与能力协商；
- LLM 权限与人工批准链；
- 数据迁移规则；
- `BAG / Build Across Games` 母品牌规则；
- 正式产品名称与 `A BAIGE Project` 家族署名规则。

### A3. 编码要求

- TypeScript 严格模式，禁止 `any` 逃逸。
- 公共函数必须有显式输入、输出和错误类型。
- 跨进程消息必须先校验再使用。
- 引擎适配代码不得反向依赖 Studio UI。
- 不得提交仅为了让测试通过而绕过真实行为的 Mock。
- 新共享包使用 `@bag/*`；不得重新引入 `@baige/*` 或 `@crossloom/*`，除非明确为迁移兼容层。
- `BAIGE` 不得作为平台、技术组件、公共 API 或 namespace 名称；仅允许用于固定署名 `A BAIGE Project` 及历史迁移说明。

### A4. 测试要求

- Bug 修复先增加复现测试。
- Schema 变化必须有往返、迁移和 Golden Test。
- 坐标与时间算法必须覆盖边界、低帧率和不同引擎约定。
- UI 功能必须至少验证命令模型与 Undo/Redo。

### A5. 交付要求

代理必须报告执行过的命令、失败的检查、未验证的假设和需要人工体验的部分。不得声称未运行的测试已通过。

## B. 产品内 LLM 编辑约束

### B1. 允许输入

默认只允许：当前文档的结构化字段、Schema、逻辑资源别名、用户选中的节点和必要动画元数据。

### B2. 默认禁止输入

完整项目目录、引擎源码、正式模型与贴图、第三方受限资产、密钥、用户隐私数据和与当前任务无关的文档。

### B3. 允许输出

LLM 只能输出符合版本化规范的 Patch、解释、诊断或模板建议。不得输出可直接执行的任意本地命令作为自动操作。

### B4. 写入流程

```text
用户请求 → LLM 建议 → Schema 校验 → 可视化 Diff
→ 用户逐项接受/拒绝 → 写入源数据 → Bridge 验证 → 引擎生成资产
```

### B5. 人工属性与审计

系统记录变更来源、影响节点、批准状态和后续人工修改。记录用于解释创作过程，不用于虚假宣称内容完全没有 AI 参与。

### B6. Provider 中立

远程 API、本地模型和离线规则引擎使用同一 Provider 接口。核心编辑器不能依赖单一模型厂商，也不能要求用户必须联网。
