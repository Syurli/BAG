# BAIGE 设计原则

## 1. 本地优先，而非云端依赖

项目源数据、正式资产、Bridge 和运行时默认在用户设备中工作。网络能力必须显式开启，停止服务不应导致工程不可编辑或不可运行。

## 2. 人工主导，而非 AI 接管

LLM 是受限的编辑建议者。所有 AI 变更必须以结构化 Patch 呈现、通过 Schema 校验、显示可视化 Diff，并由用户接受后才能进入源数据。

## 3. 设计意图独立于引擎实现

BAIGE IR 表达“播放动画、创建判定、生成特效”等领域意图，不直接保存某个引擎的类名、对象路径或私有序列化结构。

## 4. Bridge 连接引擎，不复制引擎

网页端提供快速代理预览；动画混合、物理、导航、Niagara 等真实结果由引擎权威预览确认。项目不重造完整引擎编辑器。

## 5. 源数据唯一，生成结果可重建

通用源数据是唯一人工编辑源。各引擎资产和运行时二进制是可重复生成的产物，不允许双向自由修改造成冲突。

## 6. 显式语义优先

坐标系、单位、空间、时间锚点、插值、执行顺序、默认值、继承和生命周期均必须写入规范，不能依赖引擎惯例或隐式猜测。

## 7. 所有变更可理解、可撤销、可审计

编辑命令必须支持 Undo/Redo；持久化输出必须稳定；AI 建议、人工批准、迁移和编译结果均应保留可读记录。

## 8. 能力差异应被承认

不同引擎通过 Capability 协商声明支持范围。缺失功能应警告、禁止导出或使用明确降级方案，不伪造“完全一致”。

## 9. 开放格式，避免锁定

Schema、BAIGE Bridge Protocol、基础 Runtime 和参考实现开放，使用户即使停止使用 Studio，仍能读取、迁移和维护项目数据。

## 10. 生产闭环优先于功能数量

安装、保存、校验、预览、编译、运行、迁移和文档构成一个完整功能。未形成闭环的半成品模块不计入正式支持。

## 11. 对 AI 和传统开发同样友好

规范、类型、测试和模块边界应让人类与代码代理都能快速理解。代理效率不能以牺牲架构一致性和长期维护为代价。

## 12. 隐私与最小权限是产品功能

默认只暴露完成任务所需的最小结构化上下文；正式模型、贴图、源码和无关目录不应进入 LLM 上下文。

## 13. 母品牌统一，产品身份独立

BAIGE 提供共同技术语言与品牌背书，但面向用户的领域工具保持独立产品名。官方产品统一署名 `A BAIGE Project`，不使用 `BAIGE + 功能名` 代替产品命名。
